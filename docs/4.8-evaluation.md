# 4.8. Оценка эффективности

Пункт задания 4.8: сравнение стратегий по сервису, причине, рекомендациям, времени, запросам, контексту; повторные запуски. Сценарии — пункт 4.7.

Статус: черновик спринта 1 (16.11.2026). Стратегии S1–S6 — в [4.4-algorithms.md](4.4-algorithms.md).

## 1. Сценарии

- 15–20 сценариев. Основа — встроенные поломки OpenTelemetry Demo (feature flags). Плюс несколько через Chaos Mesh: рестарт пода, сетевая задержка.
- 4–5 тренировочных: подбор настроек. Остальные — проверочные: сравнение.
- Число — от бюджета запусков, не от стенда. Уточнить после замера стоимости запуска (спринт 2).

Встроенные поломки демо (https://opentelemetry.io/docs/demo/feature-flags/):
`adFailure`, `adHighCpu`, `adManualGc`, `cartFailure`, `emailMemoryLeak`, `failedReadinessProbe`, `imageSlowLoad`, `intlShippingSlowdown`, `kafkaConsumerDead`, `kafkaQueueProblems`, `loadGeneratorVUs`, `paymentFailure`, `paymentUnreachable`, `productCatalogFailure`, `productCatalogLockContention`, `recommendationCacheFailure`, `aiRunawayAgent`, `aiSlowResponse`. У многих есть сила (доля ошибок, задержка).

### Карточка сценария

YAML в репозитории, файл на сценарий. Заполняется **до** запусков.

```yaml
id: payment-failure-30
split: test                 # train | test
inject:
  kind: flag                # flag | chaos-mesh
  name: paymentFailure
  value: 30%
ground_truth:
  service: payment
  cause_group: code_error   # одна из ~8 групп
  subtype: "Charge возвращает ошибку на 30% вызовов"
  reference_actions:
    - "проверить ошибки payment"
    - "откатить релиз или выключить проблемную функцию"
expected_symptoms:          # проверка стенда, не оценка
  - "ошибки payment → checkout → frontend"
  - "алерт по ошибкам frontend"
# время включения и выключения пишет платформа
```

- До запусков — чтобы не подгонять эталон под ответы.
- Нет ожидаемых симптомов — сценарий брак, а не ошибка системы.

## 2. Метрики качества

$R$ — множество запусков конфигурации, $s^*_r$ — виновник из карточки.

| Что | Метрика | Как |
|---|---|---|
| Сервис | $AC@k = \frac{1}{\lvert R \rvert} \sum_{r} [s^*_r \in \lbrace s_1, \dots, s_k \rbrace]$, $k \in \lbrace 1, 3 \rbrace$ | Авто |
| Причина | Доля, где $c_1$ = группа из карточки | Авто |
| Рекомендации | Средний балл 0–1–2 к правильной гипотезе по эталонным действиям | Вручную |
| Обоснованность | Доля выдуманных ссылок; доля гипотез без ссылок по теме | Авто |

Шкала рекомендаций:
- 2 — совпадает с эталонным действием;
- 1 — ведёт в правильную сторону (полезная проверка);
- 0 — не туда.

Решения:
- **Главная метрика — AC@1 по сервису.** Авто, есть в RCAEval, понятна дежурному.
- **Общей оценки нет.** Веса пришлось бы выдумать. Метрики — отдельно.
- S1 рекомендаций не даёт — в таблице «—».

## 3. Метрики затрат

| Что | Как | Откуда |
|---|---|---|
| **Токены** (главная мера) | Сумма входных и выходных по всем запросам запуска | `usage` через LLM-прокси |
| Запросы к LLM | Счётчик | Протокол |
| Время | Медиана и разброс по повторам; отдельно сбор данных и ожидание LLM | Свои замеры; S6 — снаружи + прокси |
| Неудачные запуски | Доля без нормального ответа | Протокол |
| Причины остановки S5 | Доли: сам / лимит / топчется | Протокол |
| Ошибки инструментов | Доля вызовов с ошибкой (неверный LogQL и т. п.) | Протокол |

- Деньги — не метрика: цены меняются. В тексте один раз: «при ценах модели X запуск ≈ Y».
- Токены стабильны, время шумит. Выводы о затратах — по токенам.

## 4. Подбор настроек

Только на тренировочных сценариях. Без LLM.

Что: порог $\theta$, коэффициент роста $k$, веса событий K8s, $\Delta_{before}$, $\Delta_{base}$, $d_{down}$, $d_{up}$, $K$, $\gamma$, $\delta$, $K_{stall}$. Шаблон запроса — тоже здесь.

Как:
1. По 3 значения на ручку (например, $\theta \in \lbrace 2, 3, 4 \rbrace$, $\Delta_{before} \in \lbrace 5, 15, 30 \rbrace$ мин).
2. Перебор сочетаний.
3. Мера: доля сценариев, где виновник в топ-5 рейтинга подозреваемых.
4. Лучшее. Ничья — меньше сигналов.
5. Заморозить.

В ВКР: процедура, таблица перебора, выбранные значения. Сравнения — только на проверочных.

## 5. Что сравниваем, что фиксируем

| Что | Роль |
|---|---|
| Стратегия S1–S6 | **Основная ось** |
| Лимит $C_{max}$ (например, 8k / 32k / 128k); для S6 — `--max-steps` 5 / 10 / 20 | **Основная ось** |
| Граф есть / нет | Входит в стратегии (S3 vs S4) |
| Фильтрация есть / нет | Входит в стратегии (S2 vs S3) |
| Набор метрик: RED vs RED + ресурсы | Абляция, если хватит времени |
| Пороги, окна, глубина, $K$, шаблон запроса | Подбор → заморозка |
| Температура, модель LLM, схема JSON | Фиксированы, одинаковы для всех |

Не исследуем: температуру, голосование ответов, историю прошлых инцидентов (на стенде её нет). В «ограничения» и «развитие».

## 6. Протокол эксперимента

- Каждая пара (сценарий, конфигурация) — 5 повторов.
- Сбой вносим один раз; все стратегии и повторы — на одном окне $W$.
- Запуски вперемешку: сценарий 1 — S2, S3, S4, S5, S6; сценарий 2 — …
- Все вызовы LLM — через прокси. Снимок конфигурации на каждый запуск.
- Объём: ~12 проверочных × ~15 конфигураций × 5 ≈ 900 запусков. Уточнить после замеров.

### Внешняя проверка: RCAEval RE2 / RE3

- Данные чужие: записанные случаи, виновники размечены.
- Зачем: защита от подгонки под свой стенд; сравнение с опубликованными цифрами RCAEval (BARO, их LLM-агенты).
- S1–S4: файловый провайдер читает записи → сигналы. Провайдер — пример расширяемости (п. 4.7).
- S5: записи загружаем в Prometheus / Loki, агент спрашивает как обычно. Либо MCP-сервер RCAEval — выбрать при реализации.
- Alertmanager нет: запуск вручную. Алерт — по входному сервису системы (frontend), время — из разметки. Виновника не подаём, иначе подсказка.
- Метрика — AC@1, AC@3. Причину, рекомендации, инженера не оцениваем: в разметке их нет.
- Когда: после основного эксперимента.

## 7. Графики

**Главный: AC@1 ↔ токены.**
- Каждая стратегия — линия по уровням лимита. S6 — линия по `--max-steps`. S1 — точка на нуле.
- Выше и левее — лучше.
- Ищем пересечения: «до X токенов лучше S4, выше — S5».
- Рядом — тот же график по времени.

**Кривая по шагам (S5):** AC@1 гипотез $H_k$ после шага $k$. Плато — дальше шаги не нужны.

Схема (цифры выдуманы, только форма):

```
AC@1
 1.0 ┤
     │                          ●─────● S5 пошаговая
 0.8 ┤               ▲────▲────▲       S4 однократная с графом
     │         ■────■────■             S3 без графа
 0.6 ┤   ◆────◆────◆                   S2 наивная
     │                     ○──○──○     S6 HolmesGPT (5/10/20 шагов)
 0.4 ┤ ✕  S1 только правила
     └──┬──────┬──────┬──────┬──────── токены за запуск
        0     8k     32k   128k
```
