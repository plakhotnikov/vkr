# 4.1. Аналоги

Пункт задания 4.1: анализ существующих методов и систем диагностики.

Статус: черновик спринта 1. Сверено с первоисточниками 16.11.2026: код HolmesGPT, статья AIOpsLab, репозиторий RCAEval. Вендорские обзоры — только про коммерческие продукты.

## Группы

| Группа | Кто | Для чего |
|---|---|---|
| Открытые инструменты | HolmesGPT, K8sGPT | Помочь дежурному в инциденте |
| Коммерческие продукты | Datadog Bits AI, Dynatrace Davis, Resolve.ai, Cleric | То же, код закрыт |
| Стенды и бенчмарки | RCAEval, AIOpsLab, ITBench, OpenRCA | Измерить подходы на сбоях с известной причиной |
| Научные методы | RCACopilot, RCAgent и др. | Алгоритмы из статей, источник идей |

Инструмент помогает в инциденте. Стенд измеряет подходы. Платформа ВКР — на границе: подключается к реальному стеку, как инструмент, и сравнивает стратегии, как стенд.

## Критерии

| № | Критерий | Зачем |
|---|---|---|
| К1 | Назначение: помощь в инциденте или измерение | Граница групп |
| К2 | Открытость, работа с Prometheus / Loki / Tempo / Alertmanager | Привязка к экосистеме |
| К3 | Стратегия: правила, один запрос, агент, несколько на выбор | Отличие от HolmesGPT |
| К4 | Лимиты: время, запросы, контекст | Ядро исследовательского вопроса |
| К5 | Оценка качества: есть ли, какие метрики | Связь с RCAEval |
| К6 | Учёт затрат: время, токены, стоимость | Вторая половина компромисса |
| К7 | Обоснованность: ссылки на данные, оценка инженером | Отличие от AIOpsLab |

Нет данных в первоисточнике — пишем «нет данных», не додумываем.

|---|---|---|---|---|---|---|---|

## Подробно

### HolmesGPT
- CNCF Sandbox. Сделан Robusta, большой вклад Microsoft.
- Агентный цикл: LLM сама вызывает инструменты (toolsets) и собирает данные.
- Стек почти совпадает с заданием (п. 4.5, 6.5).
- `--max-steps`, по умолчанию 100. На последнем шаге инструменты убираются — модель обязана дать итог.
- Ответ инструмента больше 15% окна контекста или 25 000 токенов — пишется на диск, в историю идёт указатель и превью.
- Перед каждым запросом: история близка к пределу окна — LLM сжимает её в краткое резюме.
- Считает токены и стоимость каждого запроса, включая сжатие.
- Общего лимита токенов на запуск нет.
- Роль в ВКР: внешняя точка сравнения (стратегия S6). Лимит — `--max-steps`; токены меряем через общий LLM-прокси.

### K8sGPT
- Анализаторы-правила проверяют объекты K8s: CrashLoopBackOff, нет эндпоинтов и т. п.
- LLM только объясняет найденное.
- Метрики, логи, трассы не смотрит.
- Роль в ВКР: пример «правила + LLM». Близко к стратегии S1 «только правила».

### AIOpsLab
- Microsoft, открыт (MIT). Живой стенд: поднимает приложение в K8s, вносит сбой, пускает агента.
- Приложения: HotelReservation и SocialNetwork (DeathStarBench).
- Сбои: сетевые и поды — через Chaos Mesh; функциональные — неверная авторизация, неверный порт, сломанный образ.
- 48 задач. В таблице статьи сумма 50 — ошибка в статье.
- Метрики: правильность (Acc@1, Acc@3), шаги, входные и выходные токены, время.
- Лимит — только число шагов. Лимитов времени и токенов в статье нет.
- Оценка автоматическая, по эталону стенда. Инженер не участвует.
- Отличие ВКР: подключение к существующему стеку (алерты из Alertmanager, данные из Prometheus / Loki / Tempo); лимит контекста как ось эксперимента; оценка инженером.

### RCAEval
- Бенчмарк RCA для микросервисов (Pham et al., WWW 2025), есть в задании [3.3].
- 9 наборов данных в трёх сериях RE1, RE2, RE3. 735 случаев сбоев, 11 типов.
- Системы: Online Boutique, Sock Shop, Train Ticket.
- RE1 — только метрики. RE2, RE3 — метрики, логи, у части систем трассы.
- У каждого случая размечены сервис-виновник и индикатор причины.
- Метрики AC@k, Avg@k. Берём AC@k.
- **Новое (2026):** режим LLM-агентов.
  - Агент работает через MCP-сервер RCAEval: метрики, логи, трассы.
  - Лимиты: `--max-steps` (30 ходов), `--max-cost-usd` (2.0 на случай). Исчерпаны — последний ход с обязательным ответом.
  - Отчёт: AC@k рядом с токенами, стоимостью, временем, вызовами.
  - Версионированный промпт. Совет авторов: сравнивать с классическим методом (BARO) на тех же данных.
  - Конвертер собирает случай из своей системы: Prometheus, OTel-трассы, выгрузка логов (в т. ч. Loki).

### Коммерческие
- Datadog Bits AI, Dynatrace Davis, Resolve.ai, Cleric.
- Закрыты. Привязаны к своей платформе. Цифры точности — от вендоров.
- Аргумент для ВКР: готовые решения сложно адаптировать к своей инфраструктуре.

### Научные методы (прочитать позже, этап алгоритмов)
- RCACopilot (Microsoft): сбор диагностики + похожие прошлые инциденты.
- RCAgent (Alibaba): агент с инструментами на локальной модели.

## Ниша ВКР

- Не «ещё один HolmesGPT». Платформа — средство.
- Вопрос: сколько качества дают лишний запрос и лишние токены? Когда хватает одного запроса, когда нужен агент?
- Вклад: отбор контекста при ограниченном бюджете по графу зависимостей.
- HolmesGPT — участник сравнения, не конкурент.

### Пересечение с RCAEval (найдено 16.11)

RCAEval-агенты: точность рядом со стоимостью, сравнение с классикой. Часть идеи «качество ↔ затраты» там уже есть.

Своё:

| | RCAEval | ВКР |
|---|---|---|
| Данные | Записанные случаи | Живой стек: Alertmanager → Prometheus / Loki / Tempo |
| Стратегии | Агенты и классика | + однократная с упаковкой по графу |
| Лимит | Защита от перерасхода | Ось эксперимента: кривая «качество ↔ токены» |
| Шаги | — | Кривая «качество по шагам» |
| Ответ | Сервис и индикатор | + группа причины, рекомендации с эталоном, проверка ссылок, оценка инженером |

Решено: S1–S5 прогоняем ещё на RE2 / RE3 — внешняя проверка на чужих данных. План — в [4.8](4.8-evaluation.md).
